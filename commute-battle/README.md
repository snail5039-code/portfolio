# 출퇴근 생존일지 (Commute Battle)

매일의 출퇴근을 기록하고, AI가 경로와 코멘트를 제안하며, 캐릭터와 배지로 습관을 게임처럼 이어가는 웹 서비스입니다. [출퇴근전쟁봇 기획](../출퇴근전쟁봇)에서 시작해 실제로 배포까지 완료한 구현체입니다.

- **배포 주소**: https://commute-battle.vercel.app
- **원본 기획 문서**: [출퇴근전쟁봇 미니프로젝트 기획](../출퇴근전쟁봇/미니프로젝트(출퇴근전쟁봇).md)

## 주요 기능

- **출퇴근 기록**: 출근·퇴근·조퇴·휴가 기록, 요일별 근무 형태(출근/재택/휴무) 설정과 연동
- **AI 하이브리드 경로 안내**: ODsay(대중교통) + TMAP(도보) 조합 경로, 실패 시 무료 OSRM으로 폴백. Google Gemini가 경로 코멘트·출발 추천 생성
- **실시간 GPS 추적 & 자동 도착 감지**: 이동 중 지도에 실시간 위치 표시, 목적지 40m 이내 GPS 3회 연속 확인 시 자동으로 도착 처리
- **캐릭터(펫) 성장 시스템**: 출퇴근 기록으로 EXP 획득 → 레벨업 시 진화, 화면을 떠다니는 펫 위젯이 시간대별/랜덤으로 말을 걸고 액세서리로 꾸밀 수 있음
- **배지 · 퀘스트**: 누적 기록 기반 배지 수집, 일간/주간 퀘스트 완료 시 EXP 보상(서버에 원자적으로 기록해 중복 수령 방지)
- **캘린더 · 통계**: 월별 기록 조회, 지각률·평균 소요시간 등 통계와 주간 리캡 공유 카드(이미지 생성)
- **커뮤니티 게시판**, **AI 어시스턴트**(대화 맥락 유지), **PWA 지원**(오프라인 페이지, 설치 유도, 알림 설정)

## 기술 스택

| 구분 | 사용 기술 |
|---|---|
| 프레임워크 | Next.js 16 (App Router) |
| 배포 | Vercel |
| 데이터베이스 · 인증 | Supabase (PostgreSQL, Auth) |
| AI | Google Gemini API |
| 스타일 | TailwindCSS 4 |

## 로컬 실행

```bash
npm install
npm run dev
```

http://localhost:3000 에서 확인합니다. Supabase·Gemini 키는 `.env.local`에 설정합니다.

| 명령 | 설명 |
|---|---|
| `npm run dev` | 개발 서버 실행 |
| `npm run build` | 프로덕션 빌드 |
| `npm run lint` | ESLint 검사 |

## 만들면서 막혔던 문제와 해결 방법

### 1. Gemini 응답이 항상 문장 중간에서 끊김
- **문제**: 경로 코멘트, 캐릭터 메시지, 어시스턴트 답변 가리지 않고 JSON이 잘려서 파싱에 실패했습니다.
- **원인**: 프롬프트를 줄이고 `maxOutputTokens`를 올려도 계속 잘렸는데, 실제로 뜯어보니 모델이 눈에 보이지 않는 "생각(thinking)" 토큰에 예산을 거의 다 써버리고 있었습니다 — 500토큰 중 476개가 생각에 쓰이고 실제 답변엔 10개도 안 남는 경우가 있었습니다.
- **해결**: 단순 구조화 출력이라 복잡한 추론이 필요 없다고 판단해 `thinkingConfig.thinkingBudget: 0`으로 생각 토큰을 비활성화하고 `maxOutputTokens`를 1500으로 넉넉히 올렸습니다. 서버에서 JSON 파싱 전에 길이(4,000자)·필드 타입 검증도 추가해서, 혹시 다시 잘려도 화면이 깨지지 않고 폴백 응답을 보여주도록 했습니다.

### 2. 자정~오전 9시 사이 기록이 하루 전 날짜로 저장됨
- **문제**: 새벽에 출근을 기록하면 통계·캘린더에서 전날 기록으로 잡히는 근본적인 버그가 있었습니다.
- **원인**: 여러 파일이 `toISOString().split('T')[0]`으로 "오늘"을 계산했는데, 이건 UTC 기준이라 한국 시간(KST, UTC+9)으로는 자정부터 오전 9시까지 날짜가 하루 어긋났습니다. 실제 출근이 몰리는 시간대라 영향이 컸습니다.
- **해결**: 로컬 날짜를 계산하는 `localDateKey()` 함수 하나로 통일해 모든 날짜 계산을 거기로 몰았습니다.

### 3. 퀘스트 보상을 시크릿 창이나 다른 기기에서 중복으로 받을 수 있음
- **문제**: 퀘스트 보상 수령 여부를 브라우저 localStorage에만 저장해서, 같은 사용자가 시크릿 창이나 다른 기기로 접속하면 이미 받은 보상을 또 받을 수 있었습니다.
- **해결**: `quest_claims` 테이블을 신설하고 `(user_id, claim_key)`에 유니크 제약을 걸었습니다. 이미 받은 퀘스트를 다시 저장하려는 시도는 DB가 그냥 거부하기 때문에, 별도 잠금 로직 없이 중복 수령을 막을 수 있었습니다.

### 4. 모바일에서 캘린더의 "통계에서 제외" 목록이 스크롤되지 않음
- **문제**: 캘린더에서 날짜를 눌러 나오는 기록 목록이 모바일 화면에서는 일정 높이 아래로 잘려서, 뒤쪽 기록의 "통계에서 제외" 버튼에 손이 닿지 않았습니다.
- **원인**: 이 목록에 PC 화면(가로로 캘린더와 나란히 배치)에서만 스크롤(`lg:overflow-y-auto`)이 걸려 있었는데, 높이를 캘린더에 맞추는 제한(`max-height`)은 화면 크기와 관계없이 항상 걸려 있었습니다. 모바일에서는 높이만 잘리고 스크롤할 방법이 없었던 것입니다.
- **해결**: 스크롤을 모든 화면 크기에서 적용되도록 수정했습니다.

### 5. 카카오맵 위에 경로 안내선이 전혀 안 보임
- **문제**: 지도 API 호출도 성공하고 데이터도 정상인데 화면에는 경로선이 아예 그려지지 않았습니다.
- **원인**: 전역 CSS의 `img, svg { max-width: 100% }` 리셋이 원인이었습니다. 카카오맵 SDK가 내부적으로 폭 0px 기준 컨테이너 안에 오버레이 SVG를 그리는데, 이 리셋 때문에 `max-width`가 0으로 계산되어 렌더링 폭이 통째로 0이 돼버렸습니다.
- **해결**: 리셋 대상에서 `svg`를 빼고 `img`만 남기는 것으로 해결했습니다. 전역 CSS 리셋은 서드파티 SDK의 내부 DOM에도 그대로 적용된다는 걸 확인한 사례입니다.

### 6. 캐릭터가 레벨업해도 겉모습이 안 바뀌는 것처럼 보임
- **문제**: EXP는 잘 쌓이는데 "펫이 진화해도 안 변한다"는 피드백을 받았습니다.
- **원인**: 두 가지가 겹쳐 있었습니다. 첫째, 진화 축하 모달이 배지 페이지의 퀘스트 보상 수령 흐름에서만 떴고, 정작 EXP를 가장 많이 얻는 "무사 도착" 경로에서는 레벨업 감지 자체를 하지 않았습니다. 둘째, 캐릭터 아이콘이 4단계 내내 같은 아이콘·같은 색이라 레벨이 올라도 시각적으로 구분이 안 됐습니다.
- **해결**: 도착 처리 함수가 레벨업 결과를 반환하도록 바꿔 축하 모달을 연결하고, 단계별로 아이콘 크기와 링/글로우 효과(무색 → 초록 → 파랑+글로우 → 금색+강한 글로우)를 다르게 주는 스타일 테이블을 추가했습니다.

### 7. 동시에 저장하면 캐릭터 EXP가 사라짐
- **문제**: 짧은 시간에 여러 이벤트로 EXP가 동시에 저장되면 그중 하나가 반영되지 않고 사라지는 경우가 있었습니다.
- **원인**: "현재 값을 읽고 → 더해서 → 그대로 덮어쓰기" 방식이라, 두 요청이 같은 값을 읽은 뒤 서로를 덮어쓰는 전형적인 갱신 유실(lost update) 문제였습니다.
- **해결**: 저장 시점에 읽었던 값과 실제 DB 값이 다르면 다시 읽어서 재시도하는 낙관적 동시성 제어로 바꿨습니다.

### 8. 퀘스트 보상 받기가 항상 실패하는 버그
- **문제**: 일부 사용자가 퀘스트 보상 받기를 눌러도 계속 실패한다고 제보했습니다.
- **원인**: "이미 보상받았는지" 체크가 퀘스트 종류를 구분하지 않는 전역 체크였습니다. 예를 들어 오늘의 일일 퀘스트 보상을 받으면, 그 기록이 포함된 주간 퀘스트(5/5 완료)가 이미 보상받은 것으로 착각되어 영원히 받을 수 없는 상태가 됐습니다.
- **해결**: 보상 수령 여부를 퀘스트 키(daily/weekly 등)별로 네임스페이스를 분리해서 저장하도록 수정했습니다.

### 9. Gemini API가 항상 503을 반환
- **문제**: 배포 환경에서 AI 관련 기능이 전부 503 에러를 냈습니다.
- **원인**: 서버 코드가 참조하는 환경변수 이름과 Vercel에 등록한 환경변수 이름이 미묘하게 달랐습니다.
- **해결**: 환경변수 이름을 한 곳으로 통일하고, 이런 실수를 빨리 알아챌 수 있도록 키가 없을 때 조용히 실패하지 않고 명확한 에러 메시지를 반환하게 했습니다.
