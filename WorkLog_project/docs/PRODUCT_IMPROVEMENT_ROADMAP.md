# WorkLog 제품 개선 로드맵

> 작성일: 2026-08-24
> 목적: WorkLog의 핵심 성격인 `일일 기록 → 주간·월간 보고 → 인수인계` 흐름을 유지하면서 상용 서비스 수준으로 발전시키기 위한 실행 문서

## 1. 제품 방향

WorkLog는 범용 프로젝트 관리 도구가 아니라 **매일의 업무 기록을 회사에서 사용할 수 있는 보고서와 인수인계 문서로 연결하는 서비스**를 지향한다.

핵심 문장:

> 작은 업무 기록을 쌓아, 보고와 인수인계에 필요한 맥락을 잃지 않게 한다.

### 유지해야 할 특성

- 타임라인을 중심으로 오늘의 업무 흐름을 보여준다.
- 일일 기록이 주간·월간 보고서의 재료가 된다.
- 기존 기록이 인수인계 문서의 근거가 된다.
- AI는 기록을 대신 만드는 기능보다 정리와 연결을 돕는 역할을 한다.
- 한국 기업 환경에서 사용하는 DOCX 보고서 양식을 지원한다.
- 메인과 내부 화면의 차분한 주황·네이비·아이보리 디자인을 유지한다.

## 2. 현재 강점

- 일일 기록, 주간·월간 보고, 인수인계가 하나의 서비스에 있다.
- AI 요약과 DOCX 다운로드가 실제로 동작한다.
- 로그인 전 미리보기와 개발자 모드가 있다.
- 타임라인을 통해 하루 업무의 맥락을 시각적으로 보여준다.
- 게시판과 댓글을 통해 기본적인 커뮤니케이션이 가능하다.

## 3. 현재 부족한 부분

### P0 — 상용화 기반

- 기록이 프로젝트, 담당자, 상태, 기한과 구조적으로 연결되지 않는다.
- 개인 중심이며 회사·팀 워크스페이스와 역할별 권한이 없다.
- 인수인계가 문서 작성에서 끝나고 수신 확인과 완료 과정이 없다.
- AI 보고서를 저장하기 전에 검토·수정하는 단계가 부족하다.

### P1 — 사용 습관과 협업

- 기록 알림, 미작성 알림, 반복 업무 생성이 없다.
- 전체 검색과 프로젝트·담당자·상태별 필터가 부족하다.
- 미완료 업무를 다음 날이나 다음 담당자에게 넘기는 흐름이 없다.
- 팀장이 팀 전체의 작성 현황과 위험 요소를 보는 화면이 없다.

### P2 — 확장성

- GitHub, Calendar, Slack·Teams 등 외부 서비스 연동이 없다.
- 업무 추세, 반복 장애물, 작성률을 보여주는 분석 화면이 없다.
- 공유 링크, PDF·CSV 내보내기 선택지가 부족하다.
- 모바일 전용 입력 경험과 오프라인 저장이 부족하다.

## 4. 목표 사용자 흐름

```text
오늘 업무 계획
  → 업무 수행 중 간단 기록
  → 상태·장애물·다음 행동 입력
  → 하루 마무리
  → AI 일일 요약 검토 및 확정
  → 주간·월간 보고서 자동 초안
  → 사용자 검토 및 승인
  → 인수인계 항목 선택
  → 후임자 전달
  → 후임자 확인 및 질문
  → 미완료 업무 승계
  → 인수 완료
```

## 5. 단계별 구현 계획

### 1단계 — 업무 기록 구조화

목표: 업무일지를 독립된 글이 아니라 연결 가능한 업무 데이터로 만든다.

- [ ] 프로젝트 엔티티 추가
- [ ] 업무일지에 프로젝트 연결
- [ ] 담당자와 협업자 선택
- [ ] 업무 상태 추가: 예정, 진행 중, 완료, 보류
- [ ] 우선순위 추가: 높음, 보통, 낮음
- [ ] 시작일과 마감일 추가
- [ ] 장애물·이슈 필드 추가
- [ ] 다음 행동 필드 추가
- [ ] 이전 기록과 후속 기록 연결
- [ ] 기존 업무일지 데이터 마이그레이션 정책 작성

완료 조건:

- 업무일지 작성 시 프로젝트, 상태, 다음 행동을 저장할 수 있다.
- 상세 화면에서 관련 이전·후속 기록을 이동할 수 있다.
- 목록을 프로젝트와 상태로 필터링할 수 있다.

### 2단계 — AI 보고서 검토 흐름

목표: AI 결과를 바로 저장하지 않고 사용자가 확인할 수 있게 한다.

- [ ] 저장 전 AI 요약 미리보기 모달
- [ ] AI 요약 직접 수정
- [ ] 다시 생성 버튼
- [ ] 요약에 사용된 원본 기록 표시
- [ ] AI 생성 실패 시 원문 저장 선택 제공
- [ ] AI 초안과 사용자 확정본 구분 저장
- [ ] 주간·월간 보고서 검토·승인 상태 추가

완료 조건:

- 사용자가 AI 요약을 확인하고 수정한 뒤 확정할 수 있다.
- 생성 실패가 업무일지 원문 저장을 막지 않는다.
- 보고서에서 어떤 기록이 근거로 사용됐는지 확인할 수 있다.

### 3단계 — 인수인계 완료 과정

목표: 문서 생성이 아니라 실제 업무 승계 완료까지 관리한다.

- [ ] 인계자와 인수자 지정
- [ ] 인수인계 상태 추가: 작성 중, 전달, 확인, 완료
- [ ] 전달 및 확인 시간 기록
- [ ] 후임자 확인 버튼
- [ ] 항목별 질문과 답변
- [ ] 미완료 업무 자동 포함
- [ ] 인수자가 미완료 업무를 자신의 업무로 가져오기
- [ ] 인수 완료 이력과 감사 로그

완료 조건:

- 누가 언제 인수인계를 확인했는지 알 수 있다.
- 미완료 업무가 담당자 변경 후에도 끊기지 않는다.
- 인계자와 인수자 사이의 질문이 해당 문서에 남는다.

### 4단계 — 팀 워크스페이스와 권한

목표: 개인 업무일지를 팀 단위 업무 흐름으로 확장한다.

- [ ] 회사·팀 워크스페이스 생성
- [ ] 팀 초대
- [ ] 역할 추가: 관리자, 팀장, 구성원
- [x] 기록 공개 범위: 개인, 팀, 회사
- [ ] 팀원별 기록 현황
- [ ] 팀 주간·월간 보고서
- [ ] 관리자용 작성률과 미확인 인수인계 현황
- [ ] 권한별 API 접근 테스트

완료 조건:

- 일반 사용자는 허용된 팀 데이터만 볼 수 있다.
- 팀장은 팀 전체 업무 흐름을 볼 수 있다.
- 개인 메모와 팀 공유 기록을 구분할 수 있다.

### 5단계 — 검색·필터·알림

목표: 기록이 쌓여도 필요한 맥락을 빠르게 찾고 기록 습관을 유지하게 한다.

- [ ] 제목·내용 통합 검색
- [ ] 기간, 프로젝트, 작성자, 상태, 태그 필터
- [ ] 저장된 필터
- [ ] 오래된 미완료 업무 검색
- [ ] 일일 기록 알림
- [ ] 주간 보고 알림
- [ ] 미작성자 알림
- [ ] 인수인계 확인 요청
- [ ] 반복 업무 자동 생성
- [ ] 사용자별 알림 설정

완료 조건:

- 여러 조건을 조합해 기록을 검색할 수 있다.
- 사용자가 알림 시간과 수신 여부를 설정할 수 있다.
- 동일한 알림이 중복 발송되지 않는다.

### 6단계 — 대시보드와 외부 연동

목표: 업무 위험을 발견하고 기존 업무 도구의 중복 입력을 줄인다.

- [ ] 완료·진행·보류 현황
- [ ] 반복되는 장애물 감지
- [ ] 지난주 대비 업무 변화
- [ ] 프로젝트별 업무량
- [ ] 인수인계 미확인 건수
- [ ] GitHub 커밋·PR 연결
- [ ] Google Calendar 일정 가져오기
- [ ] Slack 또는 Teams 알림
- [ ] Jira·Trello·Notion 링크 또는 동기화
- [ ] PDF·CSV 내보내기

완료 조건:

- 대시보드에서 지연 업무와 반복 장애물을 확인할 수 있다.
- 외부 활동을 일일 업무일지의 재료로 가져올 수 있다.
- 연동 실패가 기본 기록 기능에 영향을 주지 않는다.

## 7. 개발 원칙

- 기존 일일 업무일지와 보고서 데이터가 깨지지 않게 하위 호환을 유지한다.
- AI 호출이 실패해도 사용자의 원문 기록은 저장할 수 있어야 한다.
- AI가 만든 내용과 사용자가 확정한 내용을 구분한다.
- 삭제, 권한, 인수 완료 등 중요한 변경은 이력을 남긴다.
- 모바일에서 일일 기록 작성은 최소한의 입력으로 끝나야 한다.
- 기능을 추가할 때 메인 화면의 색상, 타이포그래피, 여백 체계를 재사용한다.
- 관리자 기능이 직원 감시 도구처럼 보이지 않도록 개인 점수보다 업무 위험과 협업 흐름을 보여준다.
