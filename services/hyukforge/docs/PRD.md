# HyukForge — 기획서

작성일: 2026-08-17 · 상태: 초안

---

## 1. 한 줄 정의

**1인 개발자가 만든 소프트웨어를 직접 배포하고, 나중에 판매까지 이어갈 수 있는 스튜디오 사이트.**

## 2. 왜 만드는가

지금 만든 결과물이 GitHub 저장소와 Vercel 배포 주소에 흩어져 있다.
사람들이 "뭘 만들었는지"를 한눈에 보고 바로 받아갈 수 있는 곳이 없다.

- 포트폴리오는 *보여주는* 곳이고, 스튜디오는 *가져가는* 곳이다. 이건 후자다.
- 지금은 무료로 뿌려서 사용자와 피드백을 모은다. 판매는 그 다음이다.
- 그래서 1단계의 성공 기준은 매출이 아니라 **다운로드 수와 재방문**이다.

## 3. 대상 사용자

| 유형 | 원하는 것 | 사이트에서 하는 일 |
| --- | --- | --- |
| 일반 사용자 | 당장 쓸 수 있는 무료 도구 | 제품 목록 → 상세 → 받기 |
| 게이머 | 가볍게 해볼 게임 | 게임 분류 → 스크린샷 확인 → 받기 |
| 개발자·채용자 | 만든 사람의 실력 확인 | 제품 목록 → 개발 기록 → 소개 |
| 나 (운영자) | 제품·버전·기록 관리 | 관리자 페이지 |

## 4. 범위

### 1단계 — 무료 배포 스토어 (지금 만드는 것)

**공개 화면**

1. **홈** — 대표 제품 1개 크게, 나머지는 표 형태 목록, 개발 기록 요약, 통계 4종
2. **제품 목록** — 분류 필터(사무용 / 게임 / 유틸리티 / 웹앱 / 실험실), 정렬
3. **제품 상세** — 설명, 스크린샷, 사양표, 버전 기록, 받기 버튼, 시스템 요구사항, FAQ
4. **다운로드 목록** — 전체 최신 버전을 표 하나로 (버전·용량·플랫폼·날짜)
5. **개발 기록** — 날짜순 변경 이력. 제품별 필터
6. **소개** — 1인칭 소개, 지금 만들고 있는 것, 연락처
7. **로그인 / 회원가입** — Google OAuth + 이메일 매직 링크
8. **내 서랍** — 내가 받은 목록, 업데이트가 있는 항목 표시, 알림 설정, 회원 탈퇴
9. **정책** — 개인정보처리방침, 이용약관

**관리자 화면** (`/admin`)

1. 제품 등록·수정·발행 상태 변경
2. 버전(릴리스) 등록 — GitHub Releases 주소 붙여넣기
3. 개발 기록 작성
4. 번역 관리 — 언어별 작성 여부를 진행률로 표시
5. 통계 — 제품별 다운로드 수, 최근 가입자

### 2단계 — 판매 (나중에)

- Gumroad 또는 Lemon Squeezy 상품 링크 연결
- 구매 확인 후 이용권(entitlement) 부여
- 라이선스 키 발급·검증 API
- 웹앱 이용권 연동
- 이 시점에 사업자등록 검토 (매출 발생 후)

### 이번에 하지 않는 것

- 결제, 환불, 정산
- 댓글·별점·커뮤니티
- 뉴스레터 발송 시스템 (알림 대상만 수집)
- 모바일 앱

## 5. 핵심 규칙

### 다운로드

- **로그인해야 받을 수 있다.** 비로그인 사용자가 받기를 누르면 로그인 페이지로 보내고, 로그인 후 원래 자리로 되돌린다.
- 받을 때마다 기록을 남긴다 (누가 · 어떤 버전 · 언제).
- 파일은 GitHub Releases에 있고, 우리 서버는 세션을 확인한 뒤 그 주소로 넘긴다.
- **한계를 명시한다:** GitHub Releases 주소는 공개다. 직링크를 아는 사람은 로그인 없이 받을 수 있다.
  전부 무료인 1단계에서는 허용한다. 유료 제품이 생기면 그 제품만 Supabase Storage 서명 URL로 옮긴다.

### 웹앱 제품

- 받기 대신 "열기"로 외부 주소를 새 창에 연다. 다운로드 기록은 남기지 않는다.

### 언어

- 지원: 한국어(기본) · English · 日本語 · 简体中文 · 繁體中文 · Español · Português(BR) · Deutsch · Français · Русский
- **한국어와 영어만 채워도 제품을 발행할 수 있다.** 나머지 언어는 영어로 폴백한다.
- 화면 문구(버튼·라벨)는 10개 언어 모두 필수. 제품 설명은 선택.
- 기계번역을 쓰더라도 사람이 한 번 훑은 언어만 "번역 완료"로 표시한다.

### 콘텐츠 원칙 (디자인만큼 중요)

- 제품 설명에 "혁신적인", "강력한" 같은 빈 형용사를 쓰지 않는다. **무엇을 하는지**만 쓴다.
- 만든 이유를 한 문장 넣는다. ("다운로드 폴더가 감당이 안 돼서 만들었습니다.")
- 알려진 버그를 숨기지 않는다. 개발 기록에 그대로 적는다.
- 통계 수치는 진짜 값만 노출한다. 0이면 0을 보여주거나 아예 감춘다.
