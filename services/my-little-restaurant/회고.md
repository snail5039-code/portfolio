# 회고 — 나만의 작은 맛집

## 배포 링크

https://my-little-restaurant.vercel.app

## 새롭게 알게 된 점

- **배포가 생각보다 훨씬 쉬웠다.** Next.js 프로젝트를 Vercel에 연결해두니, 코드를 푸시하면 알아서 빌드하고 배포까지 끝난다. 환경변수 몇 개만 잘 챙겨서 넣어주면 되는 정도였고, "배포"라는 단어가 주던 막연한 부담감이 실제로 해보니 많이 사라졌다.
- **요즘 AI는 정말 딸각 한 번이면 되는 게 많다는 걸 체감했다.** 카카오맵 API 연동, Supabase 스키마/RLS 설계, 소셜 로그인 붙이기, 공공데이터포털 API 붙여서 배지 기능 만들기 같은 것들을 하나하나 다 손으로 짜는 게 아니라, 뭘 만들고 싶은지만 얘기하면 코드 작성부터 실제 배포, 심지어 Vercel 환경변수 등록까지 대화 몇 번으로 끝나는 걸 보고 신기했다.
- **공공데이터포털 같은 정부 오픈 API도 실제로 써먹을 데가 있다는 것.** 행정안전부 모범음식점 데이터를 가져와서 내 맛집이 실제 인증 업소인지 확인해주는 배지 기능, 동네 모범업소를 지도에 자동으로 띄워주는 기능까지 만들어보면서 "이런 것도 무료로 공개돼 있구나" 싶었다.

## 느낀 점

- 예전엔 로그인 붙이기, 배포하기, 외부 API 연동하기 같은 게 다 어렵게만 느껴졌는데, 직접 해보니 "이 정도면 나도 하나 만들어볼 수 있겠다"는 자신감이 좀 생겼다.
- 다만 AI가 코드를 다 짜준다고 해도, 어떤 문제가 생겼을 때 "이게 왜 안 되는지" 방향을 잡아주고 구체적으로 확인시키는 역할은 결국 내 몫이라는 것도 느꼈다. 특히 로그인 에러처럼 화면에 뜨는 메시지만으로는 원인을 알 수 없는 경우, 실제 로그를 까보게 시키는 게 훨씬 빨랐다.

## 막혔던 부분

- **카카오/구글 소셜 로그인 연동**
  - 구글 로그인은 별다른 이슈 없이 붙었다.
  - 카카오 로그인은 두 가지 문제가 겹쳐서 꽤 오래 막혔다.
    1. `KOE205` 에러 — 일반(비즈 아닌) 카카오 앱에는 Supabase가 요구하는 `account_email` 동의항목 자체가 없어서 나는 에러였다. 카카오 디벨로퍼스에서 개인 개발자 **비즈 앱**으로 전환하고 나서야 해결됐다.
    2. 비즈 앱으로 전환하는 과정에서 Client Secret이 꼬여서 `invalid_client(Bad client credentials)` 에러까지 겹쳤다.
    - 화면에는 그냥 "로그인에 실패했어요"만 떠서 원인을 전혀 알 수 없었는데, Supabase Auth 로그를 직접 확인하고 나서야 정확한 에러 코드를 잡아서 해결할 수 있었다.
- **카카오맵 지도 표시**
  - 로컬에서는 지도가 잘 뜨는데 배포하고 나니 지도가 아예 안 나오는 문제가 있었다. 카카오 디벨로퍼스의 Web 플랫폼 설정에 배포 도메인(`*.vercel.app`)을 등록해두지 않아서 생긴 문제였고, 도메인을 등록하고 나서 해결됐다. "로컬에서는 되는데 배포하면 안 되는" 전형적인 케이스를 처음 직접 겪어봤다.
