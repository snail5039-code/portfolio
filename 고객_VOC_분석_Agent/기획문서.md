## 1. Context (배경 및 목적)

종합 쇼핑몰에서 고객 문의(VOC)가 하루 수십 건씩 들어오지만, 사람이 하나씩 읽고 분류해 긴급건을 골라내는 현재 방식은 두 가지 문제를 갖고 있다.

1. **방치 문제**: 담당자가 자리를 비운 사이 긴급 문의가 몇 시간씩 방치됨
2. **일관성 문제**: 분류 기준이 사람마다 달라 통계를 낼 수 없음

이 프로젝트는 **접수부터 분류, 기록, 긴급 알림까지 사람 손을 거치지 않는 파이프라인**을 구축한다. 담당자는 Discord 알림이 왔을 때만 개입하면 된다.

---

## 2. 시스템 구성 개요

```
[고객]
  │ 문의 작성
  ▼
Google Form ──제출──> Google Sheet (원본 응답 시트)
                          │
                          ▼
                    ┌─────────────┐
                    │     n8n     │
                    │             │
                    │ 1. 중복 확인  │
                    │ 2. LLM 분류  │
                    │ 3. 검증 안전판 │
                    │ 4. 결과 저장  │
                    │ 5. 긴급 분기  │
                    └─────────────┘
                       │        │
                긴급건만 │        │ 모든건
                       ▼        ▼
                  Discord    Google Sheet
                  채널 알림   (분석 결과 시트)
```

각자 본인 소유의 Google Form/Sheet를 사용하며, 공용 리소스는 공유하지 않는다.

## 3. 요구사항별 설계

### REQ-01. 수집 (Google Form → Sheet)

**폼 필수 항목** (항목명 고정)

| 항목명 | 형식 | 비고 |
|---|---|---|
| 문의유형 | 객관식 (결제/계정/상품/배송/기타) | 고객이 스스로 고른 값. LLM 분류 결과와 비교하는 재료 |
| 문의내용 | 장문형 | 분류의 실제 입력값 |
| 이메일 | 단답형 | 응답 회신용 |
| 물품 번호 | 단답형(5자리 숫자) | 물품 구분 번호 |

Google Form 응답은 "Sheets에 연결" 기능으로 Google Sheet에 자동 누적된다.

### REQ-02. 트리거 (Sheet → n8n)

- Google Sheets Trigger 노드를 "폼 응답" 시트에 연결하고, **폴링(Poll) 방식으로 새 행 추가를 감지**한다.
- Manual Trigger만 있는 상태는 미완성으로 간주 → 반드시 자동 트리거로 구성.

### REQ-03. 중복 방지 (LLM 호출 전 차단)

- "분석 결과" 시트를 조회하여 **동일 물품 번호**를 가진 기존 행이 있는지 확인한다.
- 존재하면 **LLM 호출 없이** 저장/알림 없이 정상 종료(NoOp)한다.
- 판정 로직은 Code 노드 또는 IF 노드로 구성, Claude Chat 노드보다 앞선 순서에 배치한다.

### REQ-04. LLM 분류 (구조화 출력)

Claude API에 문의내용을 전달하고 아래 5개 필드를 JSON으로 반환받는다.

| 필드 | 타입 | 허용값 |
|---|---|---|
| category | string | 결제/계정/상품/배송/기타 |
| sentiment | string | 긍정/중립/부정 |
| urgency | string | 상/중/하 |
| summary | string | 80자 이하 |
| needs_review | boolean | 검증 실패 시 true |

**긴급도 판정 기준** (시스템 프롬프트에 명시)
- 상: 서비스 불가, 금전적 피해, 법적 대응/언론 제보 언급, 명시적 환불 요구
- 중: 불편하지만 사용 가능, 문의/개선 요청
- 하: 단순 질문, 칭찬, 정보 확인

### REQ-05. 검증 안전판

Claude 출력이 계약을 어겨도 워크플로우가 죽지 않도록 Code 노드에서 후처리한다.

- 필수 필드 누락, 허용값 위반, 타입 불일치를 검사
- 위반 시 `urgency`는 안전한 기본값 `"중"`으로, `needs_review`는 `true`로 강제
- 검증 실패건도 예외 없이 "분석 결과" 시트에 저장

### REQ-06. 결과 저장

"분석 결과" 시트에 접수번호(VOC-YYYYMMDD-###), 원본 데이터, LLM 분류 결과, 검증 플래그를 한 행으로 append한다.

### REQ-07. 디스코드 긴급 알림

- `urgency == "상"`인 건만 Discord Webhook으로 발송 (중/하는 알림 없음)
- 메시지 필수 포함 5가지: 접수번호, 분류(category/sentiment), 요약, 원문(200자 초과 시 말줄임), 접수시각

## 4. n8n 노드 설계 (구현 순서)

| # | 노드명 | 타입 | 역할 |
|---|---|---|---|
| 1 | Google Sheets Trigger | Trigger | "폼 응답" 시트 신규 행 자동 감지 |
| 2 | Check Duplicate (Code) | Code | "분석 결과" 시트에서 동일 물품번호 검색 |
| 3 | IF Duplicate | If | 중복이면 종료, 아니면 계속 |
| 4 | Claude Chat Model | LangChain/HTTP | LLM 분류 요청 (JSON 구조화 출력) |
| 5 | Validate & Sanitize (Code) | Code | 필드 검증, 기본값 보정, needs_review 설정 |
| 6 | Generate VOC ID (Code) | Code | 접수번호 생성 |
| 7 | Append Result (Google Sheets) | Action | "분석 결과" 시트에 저장 |
| 8 | IF Urgency=상 | If | 분기 |
| 9 | Discord Webhook | Action | 긴급 알림 전송 |
