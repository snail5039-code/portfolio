# 토큰증권 권리 검증 AI 프로젝트

## 한 줄 정의

토큰증권의 투자설명서·기초자산 자료·스마트계약을 함께 분석하여, 투자자가 실제로 받는 권리와 코드로 실행되는 조건이 일치하는지 검증하는 서비스다.

## 투자 AI 프로젝트와 분리하는 이유

- 투자 AI는 상장주식의 분석·포트폴리오 운용·주문 실행이 핵심이다.
- 토큰증권 프로젝트는 발행 구조, 기초자산, 권리, 스마트계약의 일치 검증이 핵심이다.
- 필요한 데이터와 API, 규제, 평가 지표가 서로 다르다.
- 초기에는 별도 서비스로 개발하고, 향후 검증된 토큰증권 데이터를 투자 서비스가 자산군으로 조회하도록 연결한다.

## 토큰증권이란

토큰증권(Security Token)은 부동산, 미술품, 음원 저작권, 채권 등의 자산이나 계약상 권리를 잘게 나누어 분산원장에 기록한 증권이다. 일반 가상자산과 달리 배당, 수익분배, 상환, 의결권처럼 법적으로 인정되는 증권상 권리와 연결된다.

예를 들어 건물의 수익권을 여러 토큰으로 나누면 투자자는 보유 비율에 따라 임대수익이나 처분수익을 배분받을 수 있다. 따라서 핵심 검증 대상은 토큰 가격이 아니라 **토큰이 실제로 나타내는 권리**다.

## 해결하려는 문제

- 투자설명서의 배당·상환 조건과 스마트계약 실행 조건이 다를 수 있다.
- 기초자산의 가치평가와 현금흐름 근거를 일반 투자자가 확인하기 어렵다.
- 양도 제한, 투자자 자격, 의결권 같은 조건이 여러 문서에 흩어져 있다.
- 거래량이 적어 가격은 존재하지만 실제 매도가 어려울 수 있다.
- 발행·배당·상환 이벤트가 설명서대로 처리됐는지 사후 확인하기 어렵다.

## 핵심 에이전트

### 1. 문서 분석 에이전트

- 증권신고서, 투자계약, 감정평가서에서 권리 조항 추출
- 기초자산, 발행인, 수탁 구조, 담보 관계 정리
- 배당률·주기, 상환일, 수수료, 의결권, 양도 제한을 표준 스키마로 변환
- 각 추출값에 문서명, 페이지, 원문 위치 연결

### 2. 계약 검증 에이전트

- 스마트계약 소스, ABI, 배포 설정, 이벤트 정의 분석
- 설명서의 표준 권리 스키마와 실제 계약 함수를 항목별 비교
- 정적 분석, 단위 테스트, 속성 기반 테스트 결과 통합
- 불일치가 발견되면 발행·매수·이전 실행 차단 제안

### 3. 자산·위험 분석 에이전트

- 기초자산 가치와 현금흐름의 근거 검증
- 발행인·수탁기관·담보·선순위 권리 분석
- 공실, 부도, 가격 하락, 만기 지연 시나리오 계산
- 거래량, 호가 간격, 환매 조건을 이용한 유동성 위험 분석

## 검증 흐름

```text
발행 문서와 기초자산 자료 수집
              ↓
문서 분석 에이전트가 권리 스키마 생성
              ↓
스마트계약 소스·ABI·설정·이벤트 분석
              ↓
계약 검증 에이전트가 문서와 코드 대조
        ┌─────┴─────┐
       일치          불일치
        ↓             ↓
 위험 분석 및 등급화  실행 차단·수정 요청
        ↓             ↓
 사용자 리포트       재배포 후 재검증
```

검증 결과는 `일치`, `조건부 일치`, `불일치`, `검증 불가` 중 하나로 반환한다. 불일치 항목에는 문서 원문, 계약 함수, 예상 실행 결과를 함께 표시한다.

## 현재 구현 가능한 범위

국내 범용 토큰증권 주문·잔고 API를 전제로 하지 않는다. 팀 프로젝트에서는 다음 세 층을 모의 구현한다.

1. **오프체인 자산 원장:** 발행인, 기초자산, 가치평가, 현금흐름, 투자자 권리
2. **스마트계약:** 토큰 발행·이전·배당·상환·거래정지 규칙
3. **검증 브리지:** 자연어 설명서와 스마트계약 코드·실행 결과 비교

실제 자산의 소유권을 발행한다고 표현하지 않고 모든 데모 화면에 `모의 토큰증권`임을 표시한다.

## 테스트 환경

- 로컬 EVM 네트워크 또는 공개 테스트넷
- Solidity 기반 허가형 증권 토큰
- 투자자 화이트리스트와 전송 제한
- 가상 원화 또는 테스트용 결제 토큰
- 기초자산 가격과 배당 현금흐름을 제공하는 모의 오라클
- 발행·이전·배당·상환 이벤트 인덱서
- Slither 등 정적 분석 도구와 스마트계약 테스트 프레임워크

## 내부 모의 API

| 내부 엔드포인트 | 역할 |
|---|---|
| `GET /security-tokens` | 모의 토큰증권 목록과 기초자산 조회 |
| `GET /security-tokens/{id}/documents` | 투자설명서와 발행 문서 조회 |
| `GET /security-tokens/{id}/rights` | 배당·상환·의결권·양도 제한 조회 |
| `GET /security-tokens/{id}/contract` | 계약 주소·소스·ABI·검증 상태 조회 |
| `POST /security-tokens/{id}/extract-rights` | 문서에서 표준 권리 스키마 추출 |
| `POST /security-tokens/{id}/verify` | 문서·권리 스키마·스마트계약 비교 |
| `POST /security-token-orders` | 모의 매수·매도 주문 |
| `GET /security-token-events` | 발행·이전·배당·상환 이벤트 조회 |

향후 공식 인프라와 사업자 API가 공개되면 내부 API와 검증 로직은 유지하고 외부 어댑터만 교체한다.

## AI 개발 및 학습 전략

### 기본 원칙

LLM 단독으로 계약의 안전성이나 법적 효력을 판정하지 않는다.

```text
LLM: 문서 조항 추출·정규화·차이 설명
RAG: 설명서·계약서·규정·기초자산 자료 검색
코드 분석기: 함수·권한·상태변경·이벤트 분석
테스트 엔진: 배당·상환·이전 제한의 실행 결과 검증
정량 모델: 가치평가·현금흐름·유동성 위험 계산
```

### 학습 데이터

- 증권신고서와 투자계약·신탁수익증권 설명서
- 기초자산 감정평가서와 현금흐름 자료
- 스마트계약 소스·ABI·이벤트 로그
- 배당·상환·양도 제한·의결권 조항
- 문서와 코드가 일치하거나 충돌하도록 만든 합성 사례

```text
설명서: 매 분기 임대수익의 80%를 보유 비율대로 지급
스마트계약: 반기마다 수익의 70% 지급
정답: 지급 주기와 배분율 불일치, 실행 금지
```

초기에는 프롬프트, 구조화 출력, RAG로 베이스라인을 만들고 오류 사례가 충분히 쌓인 뒤 조항 분류·권리 추출·불일치 판정 모델을 제한적으로 미세조정한다.

## 디자인 기준

기준 디자인은 투자 프로젝트와 같은 **macOS 네이티브 제품군**을 사용하되, 별도의 애플리케이션으로 보이게 구성한다.

```text
┌──────────────┬──────────────────────┬──────────────┐
│ 상품·자산군  │ 투자설명서 문서 뷰어 │ 검증 인스펙터│
│              │                      │              │
│ 부동산       │ 기초자산             │ 문서 추출    │
│ 매출채권     │ 투자자 권리          │      ↓       │
│ 미술품       │ 배당·상환 조건        │ 계약 대조    │
│ 인프라       │ 주요 위험            │      ↓       │
│ 저작권       │                      │ 차이·차단    │
└──────────────┴──────────────────────┴──────────────┘
```

- 좌측은 상품 목록과 자산군 필터를 제공한다.
- 중앙은 설명서를 읽는 문서 뷰어이며 문제가 있는 원문 문장을 강조한다.
- 우측은 검증 에이전트의 문서·계약 비교 결과와 실행 차단 상태를 표시한다.
- 에이전트 결과는 채팅이 아니라 근거 위치, 계약 함수, 테스트 결과가 연결된 감사 기록으로 표현한다.
- 큰 둥근 카드, 네온 색상, 장식용 그라데이션을 피하고 시스템 글꼴과 얇은 구분선을 사용한다.

현재 디자인 목업은 `macos-finance-studio.html`의 토큰증권 화면을 기준으로 하며, 실제 구현 단계에서는 별도 앱 화면으로 분리한다.

## 단계별 로드맵

### 1단계: 권리 스키마와 문서 추출

- 가상의 부동산 수익증권 한 종류로 시작
- 설명서에서 배당·상환·수수료·의결권 추출
- 각 값에 원문 위치 연결

### 2단계: 스마트계약 구현과 검증

- 발행·이전·배당·상환 규칙 구현
- 설명서와 계약의 불일치 탐지
- 불일치 시 실행 차단

### 3단계: 기초자산과 위험 분석

- 가치평가와 현금흐름 검증
- 공실·부도·가격 하락 시나리오
- 유동성·환매 위험 분석

### 4단계: 모의 발행과 거래

- 화이트리스트 기반 모의 발행
- 매수·이전·배당·상환 이벤트 처리
- 설명서 조건과 실제 이벤트의 사후 대조

### 5단계: 외부 인프라 연동

- 제도와 공식 API가 확정된 뒤 사업자별 어댑터 구현
- 법률·보안·개인정보·전자금융 규제 검토
- 샌드박스 검증 후 제한적 실환경 연동

## 평가 지표

- 권리 조항 추출 정확도
- 설명서·스마트계약 불일치 탐지율과 오탐률
- 근거 문서·페이지·계약 함수 추적 가능성
- 배당·상환·양도 제한 테스트 통과율
- 위험 시나리오 계산 정확도
- 검증 실패 상황에서의 실행 차단률
- 발행 조건과 실제 이벤트의 사후 일치율

## 현재 핵심 가설

> 투자설명서의 자연어 권리와 스마트계약의 실행 조건을 독립적으로 비교하면, 토큰증권 투자자가 발견하기 어려운 권리 불일치와 실행 위험을 발행·거래 전에 탐지할 수 있다.
