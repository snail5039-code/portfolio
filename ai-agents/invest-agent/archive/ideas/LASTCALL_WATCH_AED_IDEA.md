# LastCall Watch · AED 기능 확장안

## 문서 상태

- 상태: 아이디어 검토
- 전제: LastCall에 워치 연동과 AED 기능을 추가한다고 가정한다.
- 미확정: 실제 테스트할 갤럭시 워치 모델, 지원 센서, 응급 감지 기준, 정식 배포 방식
- 원칙: 의료 진단 서비스가 아니라 응급 징후를 감지하고 초기 대응을 연결하는 서비스로 설계한다.

## 한 문장 설명

갤럭시 워치의 생체·행동 신호에서 이상 징후를 감지하면 사용자 상태를 확인하고, 무응답 또는 도움 요청 시 119·보호자·주변 AED·응급실 정보를 연결하는 LastCall 확장 기능이다.

## 해결하려는 문제

- 갑작스러운 이상 징후가 발생하면 사용자가 직접 휴대폰을 찾아 도움을 요청하기 어려울 수 있다.
- 주변 사람이 AED의 정확한 위치와 운영 여부를 즉시 알기 어렵다.
- 워치에서 이상 신호를 감지하더라도 신고, 위치 공유, AED 탐색, 응급실 확인이 서로 분리되어 있다.

## 제품 원칙

1. 심박수 하나로 위급상황을 판정하지 않는다.
2. 여러 센서 신호와 사용자 응답을 조합해 이상 징후만 감지한다.
3. 확정적인 질환명이나 위험 확률을 표시하지 않는다.
4. 자동 신고보다 사용자 확인과 취소 기회를 우선 제공한다.
5. 무응답 상황에서도 오탐 가능성을 고려한 카운트다운을 제공한다.
6. AED 정보의 실제 위치와 운영 상태가 공공데이터와 다를 수 있음을 표시한다.

## 예상 사용자 흐름

```text
워치 센서 데이터 수집
        ↓
개인 기준과 비교하여 복합 이상 징후 감지
        ↓
워치 진동 + "괜찮으신가요?" 확인
        ↓
┌─ 괜찮아요 → 이벤트 종료 및 기록
├─ 도움이 필요해요 → 긴급 대응 화면 실행
└─ 일정 시간 무응답 → 카운트다운 후 긴급 대응 화면 실행
        ↓
119 연결 · 보호자 위치 공유 · 주변 AED · 주변 응급실 안내
```

## 활용할 수 있는 신호

| 신호 | 예상 수집 방식 | 역할 | 비고 |
| --- | --- | --- | --- |
| 심박수 | 연속 또는 주기적 | 개인 평소 범위와 다른 변화 감지 | 단독 판정 금지 |
| IBI(박동 간격) | 지원 기기에서 연속 | 불규칙한 박동 간격의 보조 신호 | 기기·SDK 확인 필요 |
| 가속도 | 연속 | 충격, 낙상, 움직임 없음 추정 | 오탐 검증 필요 |
| 착용 여부 | 지원 기기에서 확인 | 워치를 벗은 상황 제외 | 기기별 지원 확인 필요 |
| 산소포화도 | 사용자 요청 후 측정 | 이상 감지 후 추가 확인 | 상시 감시의 주 신호로 사용하지 않음 |
| ECG | 사용자 직접 측정 | 추가 확인 자료 | 진단 용도로 사용하지 않음 |
| 사용자 응답 | 워치 화면 | 증상과 도움 필요 여부 확인 | 가장 중요한 확인 단계 |

## 기능 범위

### 1. AED 지도

- 현재 위치 주변 AED 목록과 지도 표시
- 거리, 설치기관, 상세 설치 위치, 운영시간 표시
- AED까지 이동 경로 연결
- 응급실과 AED 마커 구분
- 공공데이터와 실제 상태가 다를 수 있다는 안내

예상 데이터는 국립중앙의료원의 전국 자동심장충격기 정보 Open API다. 실제 구현 전 응답 필드, 좌표 정확도, 갱신 주기와 운영시간 품질을 다시 검증한다.

### 2. LastCall Watch

- 현재 심박수와 센서 연결 상태 표시
- 워치에서 직접 SOS 실행
- 이상 징후 발생 시 진동과 상태 확인 화면 제공
- `괜찮아요`, `도움이 필요해요` 응답
- 워치에서 휴대폰으로 긴급 이벤트 전달

### 3. 복합 이상 징후 감지

- 개인의 평소 심박 범위 학습
- 비정상적인 심박 변화가 일정 시간 지속되는지 확인
- 충격 이후 움직임 없음 여부 확인
- 워치 착용 여부 확인
- 여러 조건이 함께 충족될 때만 사용자 확인 실행
- 임계값과 판정 규칙은 의료 전문가 검토 전까지 실험용으로만 사용

### 4. 긴급 대응

- 119 전화 연결 화면
- 등록한 보호자에게 현재 위치와 상황 전달
- 구조자에게 보여줄 주변 AED 정보
- 기존 LastCall의 주변 응급실 검색 연결
- 잘못 감지한 경우 즉시 취소 가능

## MVP 범위

첫 번째 버전에서는 다음 기능만 구현한다.

1. Android 휴대폰과 갤럭시 워치 한 모델 조합만 지원
2. 워치에서 심박수와 가속도 수집
3. 심박 변화와 움직임 없음이 함께 발생하면 상태 확인
4. 워치 SOS 버튼과 오탐 취소 기능
5. 휴대폰으로 긴급 신호와 위치 전달
6. 현재 위치 주변 AED와 응급실 표시

### MVP에서 제외

- 질병 진단 및 질환별 위험 확률
- 심박수 하나만으로 자동 신고
- 모든 제조사의 스마트워치 지원
- iPhone 및 Apple Watch 지원
- AI가 독자적으로 응급 여부를 확정하는 기능
- 검증되지 않은 ECG·산소포화도 해석
- 의료기관용 환자 모니터링

## 예상 기술 구성

```text
LastCall Watch
- Kotlin
- Wear OS
- Health Services 또는 Samsung Health Sensor SDK
- 심박수·가속도 수집
        ↓ Wear OS Data Layer
LastCall 모바일 앱
- React Native / Expo 기반 기존 앱
- 위치·긴급 대응·AED·응급실 화면
        ↓
LastCall 서버
- Spring Boot
- 사용자 기준값·긴급 연락처·이벤트 기록·알림
```

기존 Expo 앱만으로 워치 센서를 직접 처리하지 않고, Kotlin 기반 Wear OS 앱을 별도로 추가하는 방향을 가정한다.

## 개발 단계와 성공 기준

1. **AED 데이터 검증 및 지도 추가**
   - 검증: 현재 위치를 기준으로 AED의 좌표, 상세 위치, 운영시간이 표시된다.
2. **워치 연결 실험**
   - 검증: 실제 워치에서 측정한 심박수와 가속도 이벤트가 휴대폰에 전달된다.
3. **상태 확인 흐름 구현**
   - 검증: 테스트용 이상 조건에서 워치가 진동하고 사용자가 정상·도움 요청을 선택할 수 있다.
4. **긴급 대응 연결**
   - 검증: 도움 요청 시 위치, AED, 응급실, 보호자 연락 기능이 하나의 화면에서 연결된다.
5. **오탐 및 배터리 검증**
   - 검증: 일상 활동 테스트에서 오탐 횟수와 시간당 배터리 사용량을 기록한다.

## 주요 위험과 대응

| 위험 | 대응 방향 |
| --- | --- |
| 센서 오차와 오탐 | 단일 수치가 아닌 복합 조건과 사용자 확인 사용 |
| 실제 응급상황 누락 | 서비스가 의료기기나 119를 대체하지 않음을 명시 |
| 워치를 벗은 상태 오인 | 착용 상태와 센서 품질 값 확인 |
| 백그라운드 측정 제한 | 실제 기기에서 측정 간격과 중단 조건 검증 |
| 배터리 소모 | 상시 고주파 측정 대신 저전력 감시 후 단계적 측정 |
| 삼성 SDK 배포 제한 | MVP는 표준 Wear OS Health Services 우선 검토 |
| 민감한 건강·위치 정보 | 최소 수집, 명시적 동의, 암호화, 삭제 기능 적용 |
| 의료기기 해당 가능성 | 진단 표현 배제 및 정식 배포 전 규제 검토 |
| AED 데이터 불일치 | 참고 정보임을 표시하고 운영기관 확인 수단 제공 |

## 구현 전 확인할 사항

- 사용자가 보유한 갤럭시 워치의 정확한 모델번호
- Wear OS 버전과 지원되는 센서 목록
- Health Services만으로 필요한 데이터가 충분한지 여부
- Samsung Health Sensor SDK 파트너 승인 필요 범위
- 워치가 화면 꺼짐 상태에서도 전달하는 실제 데이터 주기
- 워치와 휴대폰 연결이 끊겼을 때 가능한 동작
- 보호자 알림 방식과 119 연결 범위
- 국내 의료기기 소프트웨어 및 건강정보 관련 규제
- 의료 전문가에게 검토받을 감지 조건과 사용자 안내 문구

## 현재 결론

기술적으로 구현 가능한 프로젝트다. 다만 목표는 `위급상황 진단`이 아니라 `복합 센서 기반 이상 징후 감지와 응급 대응 지원`으로 제한한다. 다음 의사결정은 실제 워치 모델 확인과 센서 데이터 수집 실험 결과를 기준으로 한다.
