# 풀스택 전환 개요

기준일: 2026-08-29 KST

## 현재 판단

정적 화면 추가 단계는 일단 완료로 본다. 현재 목업은 다음 제품 흐름을 한 사이클로 보여준다.

1. 포트폴리오 상태 확인
2. 기업 상세와 근거 확인
3. 정책, 데이터, 리스크, 비용 점검
4. 리밸런싱과 전후 비교
5. 승인 전 근거 패킷 확인
6. 승인 대기와 모의승인
7. 거래 이력, 감사 로그, 결정 회고 확인
8. 역할 상태와 알림 설정 확인

따라서 다음 단계는 새 화면을 계속 늘리는 것이 아니라, React/Vite `apps/web`로 이전 완료된 19개 화면을 유지하면서 백엔드 fixture API 연결 범위를 좁게 확정하는 것이다.

## 목표

1차 풀스택 전환의 목표는 **실제 금융 API 없이 프론트엔드와 백엔드가 연결된 로컬 MVP**를 단계적으로 만드는 것이다.

- 프론트엔드는 현재 19개 HTML 목업의 화면 흐름을 컴포넌트로 재구성한다. 현재 `apps/web`에는 정적 목업 19개에 대응하는 19개 화면 이전이 완료되어 있다.
- `BACKEND-002`에서 `apps/api` FastAPI 최소 골격과 `GET /api/health`를 만들었다.
- `BACKEND-003`에서 `GET /api/dashboard`를 만들고 대시보드 화면을 연결했다. 이 화면의 데이터는 이제 서버에서만 온다.
- `/api/approvals` 등 나머지 경로는 현재 미구현이며 404가 기대 상태다.
- 사용자의 승인, 반려, 필터, 선택, 상태 변경은 로컬 백엔드 상태 안에서만 동작한다.
- 실제 계좌, 주문, 체결, 시세, 환율, DB 운영 연결은 하지 않는다. (공시는 아래 "비목표" 예외 참고)
- 모든 화면에는 `모의투자`, `가상 예시`, `실제 주문 아님`, `외부 API 미연결` 경계를 유지한다.
