## 4. 문제점

### 4-1. 반등 매수 규칙이 닿지 않는 구조 (가장 큼)

매수는 두 단계다: ① 서버 브리핑이 후보를 "매수 검토"로 골라야 ② 앱이 실시간 시세로 다시 보고 산다. 반등 신호(1분봉·VWAP)는 ②에만 있다.
14:35 후보 셋은 ①에서 이미 관찰로 끝났다. 서버에는 실시간 시세가 없는데, AI가 "장중 −13.97% 하락" 같은 **뉴스 제목**을 보고 관찰로 갔다. 그래서 ②의 반등 확인까지 가지 못했다.
→ 고칠 방향: 브리핑에 폰의 실시간 시세·1분봉을 같이 보내거나, 상승 추세 후보는 ①을 건너뛰고 ②에서 판단

### 4-2. 적자에서 흑자로 바뀐 실적을 "105.79% 증가"로 계산

삼성SDI 반기 영업이익: 전년 −8,319억 → 올해 +482억. 코드 지표 `op_income_yoy`가 이를 +105.79%로 계산해 AI에게 줬고, 투자 AI는 "105.79% 증가"로 썼다. 검증 AI는 "흑자 전환을 증가율로 쓴 왜곡"이라며 **4번 반려**했다 (10:01, 10:02, 10:33, 13:01). 코드가 준 숫자 때문에 매수 검토가 결론 없이 끝났다.
→ 고칠 방향: 전년 값이 0 이하면 증가율 대신 "흑자 전환"·"적자 지속"으로 표시

### 4-3. AI가 출처 ID를 잘못 씀

`market:KDAQ`, `market:KOSDAQD`, `snapshot:` 같이 없는 ID를 써서 반려 3번 (`snapshot`은 13:28 고침). 결론에는 영향이 없었지만 Gemini 호출이 늘었다.
→ 고칠 방향: 비슷한 ID는 코드가 바로잡기 (market은 KOSPI·KOSDAQ 두 개뿐)

### 4-4. 보유 종목 판단이 "관찰"로 나오면 엉뚱한 문장

14:49 NH투자증권: 보유 종목 질문에 AI가 "관찰"을 골랐다. 보유 종목은 보유·매도만 허용이라 코드가 '관찰'로 바꾸며 "'관찰' 대신 '관찰'로 바꿨어요"라는 위험 문장을 남겼다. 보유 종목은 '보유'로 바꿔야 한다.

### 4-5. 손절선이 걸리지 않는다

NH투자증권이 −9.16%인데 AI가 계속 "보유"를 냈다. 10/13 결정으로 손절도 AI가 판단하므로, 급락일에는 AI가 늘 "공포 매도 피하기"를 골라 손절선이 의미가 없어진다. 사용자가 정할 문제다 (예: −10%면 AI 없이 절반 손절).

### 4-6. 모멘텀 후보가 폭락일에 더 빠졌다

강한 순으로 고른 후보(고영 −14.80%, 하나마이크론 −14.77%, 피에스케이홀딩스 −12.44%)가 코스피보다 두 배 가까이 빠졌다. 많이 오른 종목은 변동성도 커서 시장이 빠지면 더 빠진다. 오늘은 사지 않아 손실이 없었지만, 반등 매수가 동작하면 이런 종목을 사게 된다. 절반 매수와 손절선이 그 대비다.
