## 2. 일반 모드와 맞춤 모드

| | 일반 모드 | 맞춤 모드 |
|---|---|---|
| 언제 | 가입 직후, 퀴즈 결과가 없거나 24개월 지났을 때, 사용자가 일반 모드로 돌아갔을 때 | 퀴즈 결과가 유효할 때 |
| AI 답변 | **정보·분석만** (공시, 지표, 장단점, 위험). "사세요/마세요" 판단 없음 | 성향에 맞춘 제안 |
| 직접 지시한 주문 | 가능 | 가능 |
| 검증 AI + 사용자 승인 | **거친다** | **거친다** |
| 한도 | 안정형 기본값에서 시작. **지금 값과 안정형 기본값 중 큰 쪽보다 올릴 수 없다** (빠져나갈 구멍 방지) | 성향 기본값. 더 올리면 저장하고 경고 |
| 행동 코치 경고 | 적용 | 적용 |

- 맞춤 모드 → 일반 모드 (`DELETE /api/profile`): 한도는 항목마다 지금 값과 안정형 기본값 중 작은 쪽
- 처음 퀴즈 (또는 일반 모드로 돌아간 뒤 다시): 그 단계 기본 한도로 바꾼다
- 퀴즈 결과가 있는 상태에서 다시 퀴즈: 한도는 내려가기만 한다
- 유효기간이 지나면: 일반 모드로 보고 맞춤 제안을 멈춘다. 한도는 그대로 두지만 올릴 수 없고, 안정형 기준으로 경고한다

## 3. 퀴즈 8문항 (구현됨)

API 보기 키는 `PUT /api/profile` 요청에 쓰는 값이다. 화면 문구는 앱이 가진다.

### A. 투자 체력 → 단계 상한

| # | 질문 | 보기 (API 키) → 결과 |
|---|---|---|
| A1 | 태어난 해는? (`birth_year`) | 19세 미만 거부. 올해 19세가 되면 "만 19세 이상입니다" 확인(`adult_confirmed: true`)이 있어야 통과. 65세 이상이면 `vulnerable` |
| A2 | 이 돈은 어떤 돈인가요? (`money_use`) | 여유자금 `spare` → 상한 없음 / 3년 안에 쓸 돈 `within_3y` → 최대 2 / 생활비 `living` → 1 + `no_buy_proposals` / 빌린 돈 `borrowed` → 1 + `no_buy_proposals` |
| A3 | 급한 일이 생기면? (`emergency`) | 비상금(3개월 생활비 이상) 있음 `fund` → 상한 없음 / 비상금 없지만 빚도 없음 `no_fund_no_debt` → 최대 3 / 고금리 빚(카드론·현금서비스 등) 갚는 중 `high_interest_debt` → 최대 2 + `high_interest_debt` |

### B. 상황 고르기 → 단계

| # | 질문 | 보기 (API 키, 점수) |
|---|---|---|
| B1 | 1,000만 원이 한 달 만에 700만 원이 됐어요 (`drop_reaction`) | 전부 판다 `sell_all`(1) / 일부 판다 `sell_some`(2) / 기다린다 `wait`(3) / 더 산다 `buy_more`(4) |
| B2 | 하나를 고른다면? 2008년 금융위기 때 실제 "최악의 해" 손실 (`portfolio_choice`). 기대 수익률은 보여주지 않는다 | `A` 원금 보장, 손실 0%(1) / `B` 채권 위주, 약 −7%(2) / `C` 주식 반·채권 반, 약 −20%(3) / `D` 주식 100%, 약 −40%(4) |
| B3 | 어제 30% 오른 종목을 친구가 강하게 추천해요 (`hot_tip`) | 바로 많이 산다 `buy_big` / 조금 산다 `buy_small` / 알아보고 정한다 `research` / 안 산다 `skip` |

- B1 + B2 (2~8점) → 2~3점 1단계, 4점 2단계, 5점 3단계, 6점 4단계, 7~8점 5단계
- B1 `sell_all`이면 최대 2단계
- **B3은 점수에 넣지 않는다.** 넣으면 급등주 추격이 "공격적 성향"으로 계산돼 상을 주는 셈이 된다. `buy_big`·`buy_small`이면 `chases_hot_stocks` 표시만 한다

### C. 지식 퀴즈 → 틀리면 −1단계

| # | 질문 | 보기 (API 키) | 정답 |
|---|---|---|---|
| C1 | 한 종목에 1,000만 원 vs 다른 업종 10종목에 100만 원씩. 한 회사가 망하면 손실이 작은 쪽은? (`quiz_diversify`) | `one_stock` / `ten_stocks` | `ten_stocks` |
| C2 | 1년에 100번 사고판 사람과 1번 산 사람. 주가가 똑같이 움직였다면? (`quiz_trading_cost`) | 100번이 더 번다 `frequent_earns_more` / 같다 `same` / 100번이 덜 번다 `frequent_earns_less` | `frequent_earns_less` |

- 하나라도 틀리면 −1단계 (최소 1단계), `quiz_missed` 표시. 응답의 `quiz_feedback`에 정답 여부와 해설이 항상 들어간다

### 계산 순서

```
단계 = B1+B2 점수 구간
단계 = min(단계, A2 상한, A3 상한, B1 상한)
C 하나라도 틀림 → 단계 − 1 (최소 1)
```

### 서로 맞지 않는 답 (`notices`)

계산은 이미 낮은 쪽을 쓰므로 막지 않고 "다시 확인해 주세요"만 알린다.
- A2 생활비·빌린 돈인데 B2 `D`(약 −40%)
- B1 더 산다인데 B2 `A`
- B1 전부 판다인데 B2 `D`(약 −40%)

### 예시

| 사람 | 결과 |
|---|---|
| 30대, 여유자금, 비상금, 기다린다 + C, 퀴즈 정답 | 6점 → **4단계** |
| 위와 같은데 C2 오답 | **3단계** |
| 카드론 갚는 중, 더 산다 + D | 8점 → 5단계 → 상한 2 → **2단계** + `high_interest_debt` |
| 빌린 돈 | **1단계** + `no_buy_proposals` |
| 70세, 여유자금, 비상금, 6점 | **4단계** + `vulnerable` |

### 그 밖의 규칙

- 퀴즈 결과 유효기간 **24개월** (`investor_profiles.expires_at`)
- 퀴즈 제출 **하루 3회** (오늘 0시 KST부터 `audit_logs`의 `profile_updated` 개수). 넘으면 429
- 저장: 출생연도만 (생년월일 전체는 저장하지 않음), 답 전체(`answers`), 표시 값(`flags`)

## 4. 표시 값(flags)은 어디에 쓰나 — 나중 단계 할 일

| 표시 | 뜻 | 쓰는 곳 |
|---|---|---|
| `vulnerable` | 65세 이상 | 4단계 투자 AI·처리안: 손실 가능성·불리한 점을 **먼저** 보여준다 |
| `no_buy_proposals` | 생활비·빌린 돈으로 투자 | 4단계 투자 AI: **매수 제안을 하지 않는다** (정보만). 직접 지시한 매수는 5단계 확인 절차를 거친다 |
| `high_interest_debt` | 고금리 빚 상환 중 | 4단계: 매수 질문에 "빚을 먼저 갚는 것이 확실한 수익"이라는 안내를 붙인다 |
| `chases_hot_stocks` | 급등주 추천에 바로 산다고 답함 | 5단계 행동 코치: 급등 직후 매수 경고를 더 강하게 (예: 한 번 더 확인) |
| `quiz_missed` | 지식 퀴즈 오답 | 4단계: 해당 개념(분산, 매매 비용)을 답변에 짧게 설명 |

## 5. 단계별 할 일 (08-dev-order.md에도 적어 둠)

### 3단계 (LangGraph 뼈대) — 완료 (2026-10-05)
- 공유 State에 `mode`(general/custom), `risk_level`, `flags`를 넣는다. 대화 시작 때 `GET /api/profile`과 같은 방식으로 읽는다

### 4단계 (투자 AI + 검증 AI) — 구현 (2026-10-05)
- **일반 모드 답변 규칙**: 투자 AI는 판단("사세요/마세요/매수 추천") 없이 사실·지표·장단점·위험만 쓴다. 제안서 `action`은 `watch`만 쓰거나 판단 칸을 비운다. 프롬프트와 검증 AI 검사 항목 둘 다에 넣는다
- `no_buy_proposals`, `vulnerable`, `high_interest_debt`, `quiz_missed` 처리 (4장 표)
- **종목 위험등급**: 국내 주식 2등급, 투자주의·경고·관리종목·해외·레버리지/인버스 ETF·ETN 1등급 (토스 준칙 별지 제4호). 검증 AI의 `risk_fit`에서 성향과 비교한다
- **결정 (2026-10-05): 완화.** 2등급(일반 주식)은 위험중립형(3단계) 이상에게 매수 제안, 1등급(투자주의·관리종목 등)은 공격투자형(5단계)만. 1·2단계는 정보·분석만
- **변동성 규칙 (확정 2026-10-06, 코드)**: 60일 변동성의 **분석 대상 안 순위**로 정한다. 위험중립형은 변동성 낮은 쪽 1/3, 적극투자형은 가장 출렁이는 20% 제외, 공격투자형은 제한 없음 (`MAX_VOLATILITY_RANK_FOR_BUY`). 고정 숫자를 쓰지 않는 이유: 2026-10 기준 30종목 60일 변동성이 29~120%(중간 69%)로, 펀드 기준(25% 넘으면 1등급)을 대면 거의 전부 1등급이 되고 시장 상황에 따라 한도가 무의미해진다. 2026-10-06 데이터로 위험중립형 10종목, 적극투자형 24종목이 매수 제안 대상
  - 검토했던 규정대로 안: 2등급을 적극투자형(4단계) 이상에게만 (증권사 기준)
  - 성향 단계와 3~6등급의 정확한 대응은 원문 표가 깨져 있어 `미확인`. 다른 증권사 준칙으로 확인할 것

### 5단계 (주문 그래프) — 구현 (2026-10-06)
- **행동 코치 규칙** (정책 검사 `functions/`에 코드로. AI 없이 계산):
  - 잦은 매매: 같은 종목을 최근 7일 안에 3번째 사고팔면 경고하고, 수수료·세금 추정액을 보여준다
  - 급등 추격: 최근 급등 종목(기준값은 구현 때 정함)이나 1등급 종목 매수 시 경고. `chases_hot_stocks`면 한 번 더 확인
  - 몰빵: 주문 후 비중이 한도의 80%를 넘으면 분산 안내
  - 처분효과: 수익 종목만 팔고 손실 종목은 계속 들고 있는 패턴이면 안내
- **성향보다 위험한 주문 확인 절차**: 일반 모드이거나 성향보다 위험등급이 높은 종목을 사용자가 직접 지시하면, 위험을 보여주고 "성향보다 위험한 주문임을 확인합니다"를 받은 뒤 진행한다 (증권사의 "부적합 상품 거래 확인서"와 같은 역할). 기록은 `audit_logs`에 남긴다
  - 이전에 남겨 둔 질문("직접 지시한 주문을 검증 AI가 반려하면 막을지")도 이 절차로 정할 것을 추천한다. 아직 사용자 결정 전

### 6단계 (Flutter 앱)

## 6. 아직 정할 것

- 계좌 크기에 비례한 한도 (예: 1회 주문 = 계좌 평가액의 5~25%): 5단계(주문 그래프)에서 검토. 지금 금액 한도(`DEFAULT_POLICIES`)는 확정 (2026-10-06)
- 투자 경험 문항: 이번에 뺐다 (지식 퀴즈가 대신). 실제 증권사는 상품별 경험을 묻는다. 행동 기반 프로필(MVP 다음 단계)에서 실제 매매 기록으로 대신할 수 있다
- **행동 기반 표시 값 (구현 2026-10-07, `functions/behavior.py`)**: `frequent_trading`, `hot_buys`, `sells_winners`. 최근 30일 기록으로 퀴즈 표시 값에 더하고(`profile_summary`), 성향 단계·한도는 바꾸지 않는다
