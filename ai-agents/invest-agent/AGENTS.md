# 작업 규칙

이 저장소에서 작업하는 사람과 AI 에이전트(Claude Code 등)는 이 문서를 따른다.
무엇을 만드는지는 [INVEST_AGENT_PLAN.md](INVEST_AGENT_PLAN.md)에 있다.

## 1. 지켜야 할 구조 원칙

- **서버는 증권사 키를 절대 받지 않는다.** 앱키·시크리트·계좌번호는 사용자 폰(Flutter 앱)에만 저장한다.
- **주문은 사용자 폰에서만 나간다.** 서버는 말 이해, 투자 제안, 검증, 처리안 작성까지만 한다. 웹(Flutter Web)에는 주문 기능을 넣지 않는다.
- **모든 주문은 투자 에이전트 → 검증 에이전트 → 사용자 승인을 거친다.** 사용자가 직접 지시한 주문도 검증 에이전트를 거친다.
- **자동매매는 사용자가 직접 켜고 한도를 정한 소액 주문만** 허용한다. 지금은 모의투자에서만 만든다. 실전 자동매매 방식은 4단계에서 사용자와 정하기 전까지 만들지 않는다.
- 자동 주문도 검증 AI를 통과해야 하고, 실행 후 알림을 보내고, 언제든 즉시 끌 수 있어야 한다.
- **기본은 모의투자다.** 실전 모드는 사용자가 설정에서 직접 켜고, 켜져 있는 동안 화면에 항상 표시한다.
- 투자 에이전트와 검증 에이전트는 서로 독립적이어야 한다. 검증 에이전트는 투자 에이전트의 결론이 아니라 제안·근거·출처만 받아서 원문을 다시 확인한다.

## 2. 작업 순서

작은 작업도 아래 순서를 지킨다. 작으면 짧게 해도 된다.

1. **계획**: 목적, 범위, 완료 기준을 정한다.
2. **확인**: 사용자에게 계획을 보여주고 동의를 받는다.
3. **구현**: 동의한 범위만 구현한다. 범위를 넓혀야 하면 다시 묻는다.
4. **검증**: 테스트를 돌리고, 화면이 있으면 직접 띄워 확인한다.
5. **보고**: 무엇을 바꿨는지, 무엇을 확인했는지, 확인 못 한 것은 무엇인지 알린다.

### 한국어 규칙

- 사용자에게 하는 답변, 문서(`.md`), 커밋 메시지, PR 설명은 한국어로 쓴다.
- 코드의 변수·함수 이름은 영어로 쓰고, 주석은 한국어로 쓴다.
- 쉬운 말로 쓴다. 꼭 필요한 영어 용어는 처음 나올 때 짧게 풀어 쓴다.

### 코딩 스타일

- 코드는 **ponytail** 플러그인(프로젝트 설정 `.claude/settings.json`에 설치됨) 방식으로 작성한다. 필요한 것만, 이미 있는 코드·표준 라이브러리 먼저, 가장 짧은 변경으로 한다.
- 단, ponytail도 그렇듯 **입력 검증, 오류 처리, 보안, 금액 계산, 주문 경로는 줄이지 않는다.** 주문·금액 관련 로직에는 반드시 테스트를 남긴다.
- 사용자가 설명을 요청하면 코드 뒤에 충분히 설명한다.

## 3. 사용자에게 먼저 물어야 하는 것

아래는 사용자가 "해도 된다"고 답하기 전에는 하지 않는다. 침묵이나 애매한 답은 허락이 아니다.

- 실제 주문, 매수·매도, 송금, 계좌 설정 변경
- 유료 서비스 가입, 결제, 비용이 생기는 설정
- 커밋 푸시, PR, 이슈, 메시지 등 외부로 보내는 것
- 배포, 공개 게시
- 파일·브랜치 삭제, 되돌리기 어려운 덮어쓰기
- 키, 개인정보, 계좌정보를 어딘가로 보내는 것
- 사용자가 정한 범위를 넓히는 것

물어볼 때는 **무엇을, 왜, 영향이 무엇인지, 되돌리는 방법**을 함께 말한다.

물어보지 않고 해도 되는 것: 이 저장소 안의 파일 읽기·검색, 요청 범위 안의 코드·문서 수정, 테스트·린트·빌드, 공개 정보 검색.

## 4. 실전투자 관련 규칙

- AI 에이전트는 실제 계좌로 주문을 내거나 테스트하지 않는다. 실계좌 주문 테스트는 사람이 직접 한다.
- 개발과 검증은 모의투자 계좌로만 한다. KB증권 모의투자가 아직 안 되면 KIS(한국투자증권) 모의투자로 주문 흐름을 검증한다.
- 실전 주문 코드는 모의 코드와 같은 흐름을 쓰고, 접속 주소와 거래 코드만 설정으로 바꾼다.
- 실전 접속 정보가 설정 실수로 섞이지 않게, 실전 모드는 명시적으로 켜야만 동작하게 만든다.

## 5. 금융 정보 규칙

- 사실, 계산 결과, 추정, 의견을 구분해서 쓴다.
- 가격, 공시, 뉴스처럼 바뀌는 정보에는 출처와 기준 시각을 붙인다.
- 확인 못 한 내용은 `미확인`이라고 쓴다. 없는 수치나 출처를 만들지 않는다.
- 수익만 말하지 말고 손실 가능성, 수수료, 세금도 함께 본다.
- "무조건 오른다", "위험 없다" 같은 표현을 쓰지 않는다.
- 뉴스는 제목, 짧은 요약, 원문 링크만 보여준다. 기사 본문을 그대로 옮기지 않는다.

## 6. 완료 기준

- 관련 테스트가 통과해야 한다. 못 돌린 테스트가 있으면 이유를 적는다.
- 화면 변경은 실제로 띄워서 확인한다.
- 실패, 경고, 확인 못 한 항목을 숨기지 않는다.
- 커밋 메시지에는 무엇을 왜 바꿨는지 쓴다.

## 7. 금지 사항

- 검증하지 않은 결과를 완료라고 보고하는 것
- 사용자가 허락하지 않았는데 허락받았다고 하는 것
- 실제 거래를 테스트나 모의라고 속이는 것
- 사용자가 만든 변경을 허락 없이 지우거나 되돌리는 것
- 서버 코드에서 증권사 키를 받거나 저장하는 것
